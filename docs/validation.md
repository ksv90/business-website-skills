# Проверка пакета и поведения

Автоматически: metadata, версии, локальные ссылки внутри переносимой папки, JSON-шаблоны,
лицензии, структура экспортируемых лидов, доказательства, блокирующие состояния,
CSV formula injection, HTML escaping, ZIP integrity и SHA-256.

Нативная установка: после сборки `bash tests/install.test.sh` проверяет установку
обоих скиллов, пути с пробелами, сохранение локальных правок, отказ при повреждённом
архиве до установки любого скилла и выбор одного скилла. В Windows CI запускается
`tests/install.test.ps1` через штатный Windows PowerShell. Для проверок используются
локальные архивы и отдельные папки внутри .build; глобальные скиллы не изменяются.

Сценарно: [поиск](../skills/business-lead-research/references/acceptance.md) и
[создание сайтов](../skills/business-website-delivery/references/acceptance.md).
Проверяйте решение и полученный результат, а не повторение текста инструкции.

Для первого полевого прогона выбрать одну нишу/город и пять организаций, зафиксировать
время и разрешённые источники. Проверить реальную долю доступных карточек, ложные выводы
об отсутствии сайта и дубли. Затем собрать один демосайт, проверить факты, изображения,
мобильную компоновку и честность формы. Не отправлять его компании без поручения.

Синтетическая fixture в tests не является списком клиентов. Для демонстрации экспортёра:

```sh
node skills/business-lead-research/scripts/export-leads.ts tests/fixtures/synthetic-leads.json .build/example-export
```

Выберите новую выходную папку при повторном запуске: экспортёр не перезаписывает файлы.
Реальный доступ к картам, CAPTCHA, качество сгенерированного сайта и выполнение GitHub
workflow проверяются отдельно. Не выдавайте успешные offline-тесты за эти проверки.
