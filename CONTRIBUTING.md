# Сопровождение

Меняйте скилл по наблюдаемой задаче или ошибке. Общие инварианты остаются в SKILL.md,
условные процессы — в тематических references, заготовки выходных документов — в assets.
Сохраняйте ссылки и самостоятельность каждого ZIP. Не копируйте один и тот же подробный
процесс в оба скилла; синхронизируйте только формат передачи данных.

Новый источник: описать операции, доступ, условия хранения, лимиты, стоимость, восстановление
и проверку актуальных официальных документов. Не добавлять провайдеру обещания по памяти.
Новая интеграция: описать полномочия, деморежим, реальные состояния и приёмку.

Перед отправкой изменений выполните команды из README и применимые поведенческие сценарии.
Тестовые компании должны быть явно синтетическими. Не коммитьте реальные базы клиентов,
персональные данные, секреты, cookies, скриншоты с доступами и клиентские материалы.
Изменения контрактов данных требуют миграции или явного повышения schema_version.

Новые ветки: `feat/...`, `fix/...`, `docs/...`, `ci/...`. Сообщения коммитов — Conventional
Commits. Просмотр, staging, commit, push, теги и публикация следуют явным поручениям владельца.
Наличие workflow не является разрешением запускать выпуск.
